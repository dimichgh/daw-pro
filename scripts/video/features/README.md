# The M39 features demo — a DJ track built on camera, three ways

What the effects suite and the drum machine actually sound like, as a narrated
film plus three complete 2-minute arrangements and six visualiser videos.

Same shape as `../session/`: everything is written into DAW Pro over the control
protocol, photographed as it is built, and narrated with numbers measured off
the renders. **Nothing here is generated by a model.** Every sound is notes and
the app's own synths, drum machine and effects.

Everything reads and writes **beside these scripts** — `out/`, `vo/`, `loops/`,
`shots/`, `work/`. Set `FEATURES_HOME` to build somewhere else.

> ⛔ Until 2026-09-21 the twelve scripts hardcoded one session's scratchpad
> (`/private/tmp/claude-501/…/<session-uuid>/scratchpad/film`). That path is
> session-scoped: in the *next* session the UUID differs, so the scripts read an
> empty or absent tree and rebuild from nothing while looking like they worked —
> and the released film lived only there, one cleanup away from gone. The base
> is now `FEATURES_HOME` defaulting to the script's own directory, resolved from
> `dirname $0` / `import.meta.url` so it holds from any working directory.

## Starlight, developed — the five ~3:30 pieces

```bash
node develop.mjs ascent --dry          # the WHOLE plan, offline, in a tenth of a second
node develop.mjs ascent                # ~6 min: build + render (timeout handled internally)
python3 section-arc.py cosmic-ascent   # does it ACTUALLY develop? three gates, written to fail
bash master-cosmic.sh                  # levels every out/cosmic-*/ to -18 and to each other
bash page-audio.sh                     # full-length matched MP3s for the review page
python3 section-arc.py cosmic-ascent cosmic-collapse cosmic-heartbeat \
        cosmic-aurora cosmic-signal --json      # writes out/page-data.json
python3 review-page.py > out/review.html        # the page, generated FROM those numbers
./make-viz.sh cosmic-ascent                     # long + short visualiser for one piece
```

⭐ **`--dry` is the cheap gate and it exists because the expensive one is ten
minutes.** It prints every section, its layer gate, its note counts and the whole
automation sweep — including a duplicate-beat check and a **sweep-threading
check** that both refuse — without opening the socket. A form-table mistake is
caught before the app is touched.

⛔⛔ **DO NOT RUN FFMPEG WHILE A RENDER IS IN FLIGHT.** They share one machine and
the render is the one on a clock. A `section-arc.py` pass is ~70 ffmpeg
invocations; running one during a re-render of `ascent5` pushed that render past
its timeout and **lost ten minutes of work with a truncated stack trace as the
only evidence**. The app was never wedged — measured at 104% CPU throughout,
which is how the diagnosis was made rather than guessed. Measure *between*
renders, never beside them.

⚠ **AND DO NOT PIPE A RENDER THROUGH `head`.** `node develop.mjs … | head -40`
shows nothing at all until 40 lines accumulate, so a running render and a dead
one look identical. `tail -3` is worse in the other direction: it is what threw
away the actual error message above and left only `at process.processTimers`.
Filter with `grep -E`, which is line-buffered, or write the whole log.

## The five-minute cuts

```bash
node develop.mjs ascent5 --dry     # 80 bars, 5:05 — same flags, `5` suffix
```

⭐ **A five-minute piece is not a 3½-minute piece with longer sections.** Each
`*5` form adds a **second wave**: the music pulls back further than its first dip
went, returns an octave up, and spends its longest section on one unbroken climb.
Bars are computed per tempo — `round(305 × tempo ÷ 240)` — so 80 bars at 63 BPM,
66 at 52, 92 at 72, 84 at 66. The same number at every tempo would have produced
lengths from 4:27 to 6:09.

⛔ **AND EVERY PEAK MUST BE HIGHER THAN THE LAST.** The first cut of these had a
second climax no bigger than the first — measured, 0.1 dB louder and 1.0 dB
brighter after a two-minute wait, which is a repeat, not a development. Gates
①②③ all passed it. That is what **gate ④** in `section-arc.py` now exists for.

⛔ **The beatless rule still holds, with ONE scoped exception.** A–D and three of
these five have no pulse at all. The user asked, in their own words, for *"2
versions each, one with pulse"* — so `heartbeat` and `signal` have one, and both
still **end** beatless. The ruling is written into `cosmic.mjs`'s header at the
point of refusal so it cannot be re-refused by a future session reading only the
prohibition.

## The looping Shorts

    python3 make-loop.py cosmic-ascent-5m        # find + cut the 8-bar window
    python3 master-loop.py out/…/…-loop.wav      # gain to platform loudness
    python3 verify-loop.py out/…/…-loop.wav      # judge it, with a live control
    bash make-loop-short.sh                      # render the vertical video

⛔ **A LOOPING SHORT GETS NO OUTRO CARD.** `viz-outro-port.mp4` is 2.4 s of
DIGITAL SILENCE (−inf dBFS, measured). `make-viz.sh` concatenates it onto every
Short, which means those Shorts loop as music → nothing → music. The brand it
carried goes in-frame instead. Do not "restore" the card here.

⛔ **`--bars` MUST BE A MULTIPLE OF 8** and `make-loop.py` refuses otherwise. The
chord cycle in `cosmic-material.mjs` is 8 bars, indexed by absolute bar. Any other
length restarts on a different chord.

⭐ **The loop does NOT start and end on the same chord.** It cannot: 8 bars over
an 8-bar cycle starts on chord N and ends on chord N−1. The property that makes
it seamless is that the chord *following* the end is the chord at the start. Do
not "fix" a loop to satisfy the other, wrong-sounding statement.

⛔⛔ **`verify-loop.py` RUNS ITS POSITIVE CONTROL ON EVERY INVOCATION, AND THAT IS
NOT CEREMONY.** Two earlier versions of that file printed a confident ✅ for all
five real loops while being completely unable to detect the defect they existed
to catch — spectral flux cannot see a wrong chord arriving under a crossfade, and
broad-band spectra could not separate one from an ordinary chord change. The
control was the only thing that ever caught either. If it ever reports the
planted copy as passing, the verdicts above it are worthless.

⚠ **Loudness: the loops go to ~−14 LUFS, the full pieces stay at −18.** Not an
inconsistency. The pieces measure LRA 13–17 because they are built to start near
silence and arrive; the integrated figure averages that arc, and raising it means
compressing the development. A loop is cut from the climax, LRA 2–4, so plain
gain reaches platform loudness with nothing squashed. `master-loop.py` REFUSES to
limit and reports the shortfall instead — three of the five stop 1.1–1.5 LU short
because true peak runs out, and closing that is a tone decision somebody makes.
⭐ Target −1.0 dBTP and re-measure the **encoded** file: AAC overshoots (one loop
left at −1.0 measured −0.9 after encoding).

## The three variants are ONE AXIS APART

Same drum machine, same 909 kit, same drum patterns, same effect chain, same
64-bar structure, same 128 BPM. **Only the melody differs** — which is the point:
a preference between them is then real information, not a reaction to six things
changing at once.

| id | source | key | LUFS | dBTP | drop vs intro |
|---|---|---|---|---|---|
| `machine-room` | original | A minor | −15.6 | −1.0 | +6.4 dB, +33.1 dB brighter |
| `mountain-king` | Grieg, 1875 | B minor | −15.5 | −1.0 | +6.6 dB, +34.1 dB brighter |
| `fate` | Beethoven, 1808 | C minor | −15.4 | −1.0 | +6.7 dB, +34.2 dB brighter |

Both classical themes are public domain many times over. Their pitches were
traced from the **LilyPond source text** Mutopia publishes beside its engravings,
not read off an image — see `MELODIES.md`, which also records what is *not*
transcribed: Beethoven's continuation past the four-bar motif is ours, disclosed.

## Four things this build learned the hard way

1. **⛔ A shipped effect can be configured, photographed and rendered while doing
   nothing.** `dynamicEQ`'s `bandNMode` defaults to 0, which the app documents as
   "a TRUE no-op — the band's filter is not even run". Six band parameters were
   set and the mode never was. The render with the knobs set came out
   **byte-identical (same md5)** to one at defaults. *Distinct bytes prove
   nothing; assert the physics.* Now: mode 1 at threshold −42 dB, a measured
   2.3 dB of gain reduction at 90 Hz.
2. **⛔ Editor cards cannot be closed.** `view.openEditor` takes only
   `trackId`/`effectId`; `view.closeEditor` does not exist. An instrument card is
   a separate layer effect cards do not replace. So every *clean* shot must be
   taken before the first card opens — hence `build.mjs`'s two passes.
3. **⛔ A research report that disagrees with itself is wrong somewhere.** The
   first Grieg transcription described "upward scalar motion" and produced a
   repeated-note cell. The visualiser showed the tell: one bright line at a
   single pitch where the theme has to climb a fifth.
4. **⛔ Automation does not move the effect card's knob during playback.** It
   drives the render correctly (+33 dB brighter drop) but the card shows its
   authored value. Real defect, open, outside this wave's scope.

`STATUS.md` carries the full list, including the MUST-NOT-CLAIM set — most
importantly that **the drum machine has no editor card**, which the film states
out loud rather than staging a panel that does not exist.
